# Human Rating & Response Quality Evaluation Guide

This guide explains how genuine human ratings are collected, validated, imported, and evaluated within the SpotifyCares AI Support System.

---

## 1. Overview & Integrity Protocol

> [!IMPORTANT]
> **Zero Fabrication Policy**: In compliance with assignment integrity standards, human ratings are **never** automatically generated, inferred, guessed, or randomized.
>
> - The human rating template (`data/human_rating_template.json`) is initialized with `null` scores for all 30 candidate evaluation examples.
> - Evaluation metrics strictly distinguish between:
>   1. **`REAL_LLM_JUDGE`**: Scores generated by a live LLM API (OpenAI/Gemini).
>   2. **`HUMAN_RATINGS`**: Genuine scores explicitly provided by human evaluators.
>   3. **`NON_LLM_FALLBACK`**: Heuristic fallback scores used when the real LLM API is unavailable (e.g. rate limits / missing API keys).
> - Agreement metrics between LLM Judge and Human Ratings are computed **only** when genuine human ratings have been imported.

---

## 2. Rating Dimensions & Scoring Rubric

Human evaluators rate proposed support replies across four core dimensions on a 1–5 integer scale:

| Dimension | Weight | Definition | Scale (1-5) |
|---|---|---|---|
| **Relevance** | 30% | Does the reply directly address the customer's specific problem? | 1 = Off-topic, 5 = Perfectly targeted |
| **Groundedness** | 30% | Is the reply strictly based on retrieved historical evidence without hallucination? | 1 = Completely fabricated, 5 = 100% grounded |
| **Helpfulness** | 20% | Is the response actionable, polite, and practical for the user? | 1 = Unhelpful/confusing, 5 = Solves problem cleanly |
| **Correctness** | 20% | Are all steps, links, and technical advice factually accurate? | 1 = Factually incorrect, 5 = Completely accurate |

**Weighted Overall Score Formula**:
$$\text{Overall Score} = 0.30 \times \text{Relevance} + 0.30 \times \text{Groundedness} + 0.20 \times \text{Helpfulness} + 0.20 \times \text{Correctness}$$

## 3. Structured Input Format

To submit ratings, create a JSON file (e.g., `ratings_input.json`) structured as a JSON array of objects:

```json
[
  {
    "id": "GOLDEN-001",
    "relevance": 5,
    "groundedness": 5,
    "helpfulness": 4,
    "correctness": 5,
    "notes": "Clear troubleshooting instructions provided."
  },
  {
    "id": "GOLDEN-005",
    "relevance": 4,
    "groundedness": 4,
    "helpfulness": 3,
    "correctness": 4
  }
]
```

### Validation Constraints
1. **Dimension Values**: Must be integers between 1 and 5 (inclusive).
2. **Valid Candidate IDs**: Every `id` must exist in the 30-example sample set (`data/judge_sample.json` / `data/human_rating_template.json`).
3. **No Duplicates**: The input file cannot contain duplicate IDs.
4. **Mandatory Fields**: All 4 rating dimensions (`relevance`, `groundedness`, `helpfulness`, `correctness`) are required for each entry.
5. **Overwrite Protection**: Importing ratings for an ID that already has ratings in `data/human_ratings.json` requires the `--overwrite` flag.

## 4. Import Workflow & Commands

### Step 1: Import Human Ratings
To import your completed human ratings into the system:

```bash
python -m scripts.import_human_ratings --input path/to/your_ratings.json
```

If re-submitting or updating existing ratings:
```bash
python -m scripts.import_human_ratings --input path/to/your_ratings.json --overwrite
```

### Step 2: Compute Agreement Metrics
After importing genuine human ratings, calculate agreement statistics (Exact Agreement %, Within-1-Point Agreement %, Quadratic Weighted Cohen's Kappa) between the LLM Judge and Human Ratings:

```bash
python -m src.agreement_metrics
```

### Step 3: Generate Response Quality Summary
To compute the aggregate response quality report across all evaluated dimensions and system components:

```bash
python -m scripts.compute_response_quality_summary
```

---

## 5. File Artifacts & Storage Locations

- **Unfilled Template**: `data/human_rating_template.json` (30 examples, all human fields initialized to `null`).
- **Imported Ratings**: `data/human_ratings.json` (stores imported ratings and metadata).
- **LLM Judge Outputs**: `data/llm_judge_results.json`.
- **Agreement Metrics**: `data/judge_human_agreement.json`.
- **Response Quality Summary**: `data/response_quality_summary.json`.
